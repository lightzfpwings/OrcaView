## Obtaining and rebuilding the libraries

Download the companion source ZIP next to the platform packages on the release page. Open the source archives inside it to read the copyright information specific to each component, including each Qt module's LICENSES directory and its third-party sources. The Qt WebEngine module archive contains the code for the Designer and PDF image-format plugins included in the wheels. The platform bundles contain no QtWebEngineCore library or Chromium web engine executable.

The Qt runtime libraries are dynamically loaded. In the macOS application the frameworks are in `Contents/Frameworks/PySide6/Qt/lib`. Rebuilding with `packaging/macos/OrcaView.spec` incorporates the Qt libraries from the build environment and ad-hoc signs the resulting app. In the extracted Windows package the bindings and libraries are under `python/Lib/site-packages/PySide6`. On Linux they are under `python/lib/python3.13/site-packages/PySide6`, including the `Qt/lib` subdirectory. You may replace the libraries with ABI-compatible builds, rebuild the bindings, or debug modifications to the libraries. The project build recipe and dependency checksums are in `packaging/desktop/`. Qt source archives include upstream build instructions. [Qt for Python build instructions](https://doc.qt.io/qtforpython-6.8/building_from_source/index.html)

ORCA is an external application with its own licensing and installation procedure. The portable packages do not contain its executable or the Multiwfn engine.

The real ORCA output fixtures retain the program's upstream credits, trademarks and citation notices. The repository's MIT license covers OrcaView's contributions.
