# OrcaView 分阶段路线图

基线：软件 `0.1.0a1`、架构 `prototype-1`、项目 schema 1/2；设计日期 2026-11-12，实现状态更新2026-11-19。P0原型可运行，M1首批数据底座独立验收通过，完整M1和G0跨模块仍未完成。路线图描述阶段顺序与验收条件，不承诺未经验证的完成日期。

## 两条独立主线

建模与计算主线按 P1–P3 推进；分析主线可以直接使用已有 ORCA 文件，从 A1 开始，不等待分子编辑器或本地 runner。P4/P5 描述的结果和渲染能力纳入分析主线，不表示它们必须等到 P3 结束才开发。

| 分析阶段 | 交付重点 |
|---|---|
| A1 | 原生结果、来源/几何/单位契约、优化/振动/谱图和基础 Cube 显示 |
| A2 | 内置 Multiwfn 来源核心：分子加载、C ABI、自有 worker、批量求值/积分、Mayer/Hirshfeld 与内部 ESP；原版用于对照，之后扩展 RDG/IRI |
| A3 | 电荷/键级扩展、ELF/LOL、拓扑/盆积分与多状态反应性 |
| A4 | ORCA 原生 NTO/光谱及经输入链路验证的高级激发态分析 |

输入矩阵与验收见 [POSTPROCESSING.md](POSTPROCESSING.md)。完整分子功能与周期排除见 [手册筛选](research/MULTIWFN_MANUAL_MAP.md)，NBO 等依赖见 [外部依赖清单](research/MULTIWFN_EXTERNAL_DEPENDENCIES.md)。以上是 `analysis-design-2` 的待实施设计，当前没有可调用的 Multiwfn 数值核心。

### 内置分析核心 K0–K4

| 阶段 | 交付重点 |
|---|---|
| K0 | 锁定官方源码、依赖、参考数据、非周期能力与可复现构建范围 |
| K1 | 去掉原主程序/交互依赖，分子加载、批量点值/导数、新 C ABI 与单体系 worker |
| K2 | 网格、内部 ESP、原有解析/数值积分与 Mayer/Hirshfeld 数组接口，完成首个真实数值闭环 |
| K3 | 拓扑、盆域、fuzzy 积分、局域化等逐项分离参数与结果，复用计算体 |
| K4 | 激发态、响应与高级分子分析，按证据推进全局状态上下文化 |

K0–K2 支撑 A2，K3/K4 按依赖分别支撑 A3/A4。原版 CLI 是对照与可选 fallback；内置引擎不以“外部模式先出现性能瓶颈”作为启动条件。精确源码证据、拟议 API 与验收见 [MULTIWFN_ENGINE_DESIGN.md](MULTIWFN_ENGINE_DESIGN.md)。本次交互设计在保留阶段依赖的基础上，细化 P1–P3 和结果工作区。

## GaussView 6 对照后的交互优先级

交互修订 `interaction-design-1`，详见 [功能对照与交互规格](GAUSSVIEW6_ALIGNMENT.md)。已有规划不计为已有实现；下表是本次新增或细化的交付要求。

| 顺序 | 交付要求 | 纳入阶段 |
|---|---|---|
| 1 | 稳定原子 ID、有序/集合选择、完整编辑事务、不可变几何与结果引用 | P1 / A1 数据底座 |
| 2 | 精确几何编辑、片段连接预览、受控补氢、可撤销清理 | P1 |
| 3 | 频率/谱/动画联动、MO/能级/表面导航、结果帧派生任务 | A1 / P5，任务执行由 P3 承接 |
| 4 | 可视化约束与一维扫描、实际点与结构联动 | P2 / A1 扩展 |
| 5 | 多模型比较、多谱叠加与有条件的构象加权；二维扫描、NMR/路径专题 | A1/A3/A4 扩展 |

分析查看不等待 runner；生成派生任务可先导出输入，实际启动遵守 P3。多模型/多视图契约提前到 P1，比较界面随结果模块交付，P6 负责完善与发布。

## P0：可运行架构与交互原型

**当前交付范围。** 单文档桌面壳、CPU 球棍投影、XYZ 单帧读取、旋转/缩放/选择/测距、全部 118 个元素符号与电子数检查、SP/OPT/FREQ/OPT_FREQ 基础输入生成、导出、项目快照、未保存变更提示与关闭保存处理、单作业输出摘要、无 Qt 的 CLI。核心和 GUI 分离，保存采用显式 schema。

输入方法限定为 HF、B3LYP、PBE0、PBE，基组限定为 def2-SVP、def2-TZVP、def2-TZVPP。识别全部元素符号不等于上述方法/基组覆盖全部元素；显示半径只有常用子集有专用参数，其余采用回退值。

当前界面中的分子图形用于查看已有结构；添加原子、修改键、移动原子、撤销/重做、本地运行、振动、轨道、谱图均未实现。

验收要求：

- CLI 可在不安装 PySide6 时读取示例并生成基础 ORCA 输入。
- XYZ 格式错误、非有限坐标、未知元素和不相容电子数能够给出明确错误，不覆盖当前有效文档。
- 项目读写能保留结构与设置；拒绝未知 schema，保存失败不破坏旧文件。
- 旋转、缩放和选择不改变分子科学坐标；测距与核心几何计算一致。
- 输出摘要区分正常结束、SCF、几何收敛与未知；频率未完整解析时不宣称科学成功。
- 桌面窗口可启动并进行视觉检查；真实 ORCA 执行不是本阶段验收内容。

本文件不填写测试通过数量。每次交付应依据当次实际运行的测试与 GUI 检查报告结果。

## P1：分子编辑器与文档契约

**建模主线下一优先级。** 让用户能够建立并修改结构，而不仅是查看已有 XYZ。先稳定文档模型和编辑行为，再扩展计算自动化。分析主线同时可以从导入已有计算独立起步。

交付内容：

- `MoleculeDocument`、稳定原子 ID、修订号、编辑命令与撤销/重做。
- 元素选择、添加/删除/替换原子、添加/删除键、显式键级与片段插入。
- 坐标表编辑，以及距离、键角、二面角的测量和受控修改；指定固定端/移动原子集合，提供预览、确认、取消与完整撤销。
- 有序选择、框选、按元素/连接片段扩展及保存选择集；原子表与三维共享稳定 ID。
- 常用片段连接点预览、受控补氢；适用元素与价态不明时保留人工选择。
- 提前定义 `GeometryRef`、`ModelCollection` 与多视图引用，结果和波函数始终绑定不可变几何。
- 显式区分人工键与距离推断连线；不把视觉连线当作完整化学感知。
- 可选几何清理适配器；运行前说明适用元素、失败行为与来源。未经清理不阻止用户保留原始结构。
- 将已有未保存状态与关闭保存处理扩展到结构编辑的文档历史；加入修订、撤销/重做、导入错误恢复与版本化项目迁移。

验收要求：

- 编辑、撤销、重做可往返恢复原始几何、键及电子态，选择通过稳定 ID 跟随编辑。
- 旋转视图与移动原子具有清楚、不同的操作模式；模式提示可见。
- 删除原子后不存在悬空键或失效约束；跨面板索引保持一致。
- 至少以小分子、环结构与带电/开壳层示例验证操作；显示参数与化学能力边界可见，不能把元素识别当作方法/基组适用性证明。
- 当前核心接口和 schema 1 数据有明确兼容或迁移路径，不能直接改变旧字段含义。

## P2：ORCA 输入能力与可解释校验

交付内容：

- 版本化 ORCA 能力清单；结构化模板与目标引擎版本绑定。
- 常规 SCF、网格、溶剂、优化约束与资源选项；优先小而明确的功能子集。
- 点选坐标创建约束/扫描对象；先验证一维距离/角度/二面角扫描，保存单位、实际点列表、原子映射与输入转换规则；二维后续。
- 最近设置/个人模板，以及逐原子基组/ECP 的独立适配；每种模板分别验证。
- 从指定结果帧或显式振动位移创建派生结构与输入，记录父来源，不覆盖旧任务。
- 参数来源、默认值与冲突解释；区分词法合法、配置相容与科学适用性。
- 高级原文编辑模式，明确结构化面板能否继续编辑；未知语法保留原文，不能误称完整往返。
- 输入预览、输入哈希和计算快照，为本地运行建立不可变输入。

验收要求：

- 同一科学对象和设置生成确定性输入，结构化字段不能注入任意换行/block。
- 资源界面明确 `%maxcore` 是每核/进程内存设定，并说明总量估算。
- 每个模板有官方语法依据、代表性输入和负面案例。
- 高级编辑后的原文不会被面板静默覆盖；版本或方法不支持时说明原因。

## P3：本地 runner 与任务记录

在 P1 文档修订和 P2 输入快照稳定后实施。此阶段只做本地运行，不引入 Slurm/PBS 或远程任务系统。

交付内容：

- `JobRecord` 和状态机：草稿、校验、预检、就绪、运行、解析、完成/需复核/失败/取消。
- 可执行文件、版本、权限、并行环境、工作目录及资源预检；只使用已验证的完整可执行路径。
- 独立工作目录、输入快照、参数列表启动、进程组取消、标准输出/错误日志。
- 运行进度与日志增量读取，UI 不阻塞；应用重启后能识别已有任务而不重复启动。
- 区分退出码、结束标记与任务专属收敛；保留缺失证据为 unknown。
- 失败保留输入、输出与日志；仅隔离本次新增且可确定无用的杂项。

执行约束：使用参数列表，无 `shell=True`；不在 ORCA 驱动程序外包 `mpirun`。预检失败呈现错误并写日志，停止启动；重检成功后归档旧错误日志。每次重试建立新任务或明确的尝试记录，不覆盖旧证据。

验收要求：

- 用受控的替身程序验证成功、非零退出、缺失结束标记、超时/取消、部分写入与重启恢复路径。
- 进程失败不能覆盖输入；取消后不遗留由本任务启动的活动子进程。
- 明确记录“框架验证”与“真实 ORCA 验证”；真实验证仅在可用且授权的 ORCA 环境中进行。
- 真实 ORCA 验证至少分别覆盖单点、优化与一次失败案例，并保存版本、输入、输出、日志与结论依据；没有真实环境时如实列出未验证部分。

## P4：结构轨迹、振动与常规性质

交付内容：

- `ResultDataset` 与结果适配器注册，记录解析器版本、文件来源、单位、几何索引和缺失项。
- 可用时优先 `property.json`，文本输出作为证据与回退；区分波函数 JSON 与性质 JSON。
- 优化轨迹、能量/收敛曲线、步数与分子视图联动。
- 频率表、模态动画、IR/Raman 谱图与参数化展宽。
- 结果原始值与显示转换分离；图表导出保留单位和参数。
- 文件组导入的关联检查；文件同名不是几何/波函数一致性的证据。
- 频率/谱/动画共享模态 ID；虚频正负位移显式生成候选结构，动画幅度不改写平衡几何。
- 多谱叠加、原始棒谱/展宽曲线、实验数据与手动权重；构象 Boltzmann 加权在数据与条件齐备后扩展。
- 多模型比较与结果帧派生入口；扫描/IRC/NEB 按独立解析能力扩展，保留实际帧、坐标定义和缺失点。

验收要求：

- 能量、频率、坐标、强度的单位有明确来源；`GeometryIndex` 不发生一位偏差或误绑末帧。
- 优化、频率与结构修订可以互相追溯；动画不改写平衡结构。
- 结果缺失、截断、版本差异、虚频与非收敛有可见状态；程序正常结束不能被解释为极小点证明。
- 线性/非线性分子模态、零/近零频率和虚频显示经过代表性样例核对。

## P5：轨道、Cube 与高级三维后端

交付内容：

- 渲染适配器接口与可选 VTK 后端，保留原型后端用于轻量场景。
- Cube 体数据、轨道正负相位、等值面阈值、透明度与可见层。
- 与能级/占据列表联动的轨道查看；按波函数、表示、自旋与原始轨道编号定位，不用排序行号作为身份。
- 网格、表面、映射场与显示层分开管理；电子密度与静电势等映射根据可用数据逐项加入。
- 并排/叠合比较可统一相机、等值面阈值与色标；对齐仅为显示变换，保留原始坐标。
- 通过匹配 ORCA 版本的官方工具处理 `.gbw`，保留生成参数、输入来源与产物记录。
- 缓存容量、异步生成、取消、大网格性能边界与失败提示。

验收要求：

- 网格原点、轴方向、单位、标量顺序和分子坐标一致；正负轨道不混淆。
- 缺少外部工具时基础分子查看、项目读写和输入生成仍可使用。
- 大体数据不阻塞主线程；失败不损坏原始波函数文件。
- 源文件、生成命令参数、工具版本和等值面设置可追溯。

## P6：可选适配与发布完善

在核心工作流稳定后评估 OPI 适配、更广泛的性质、多文档/视图交互完善、安装包、国际化和用户偏好。OPI 与 ORCA 的版本要求单独锁定；OPI 不作为读取已有结构和生成输入的强制依赖。

交付前完成 Linux 主要桌面环境的安装和运行验证，macOS 单独记录支持范围。正式支持矩阵应列出 Python、Qt、ORCA、可选渲染和外部工具版本，并为不支持的组合给出明确提示。

## 每一阶段的交付清单

1. 更新功能范围与公开契约，标明实现、实验、待规划的状态。
2. 为新模块给出输入/输出对象、版本、错误语义与旧数据迁移。
3. 提供可复核的示例、必要测试、实际执行记录与 GUI 视觉检查。
4. 保留失败证据；不把静态检查、样例输出或替身程序结果写成真实 ORCA 成功。
5. 在上一阶段契约稳固后迁移下一项责任；外部执行、解析与渲染不合并进单个主窗口脚本。

设计依据与官方来源见 [DESIGN.md](DESIGN.md)。
