# Multiwfn 分子分析的外部软件与数据依赖

修订日期 2026-11-12，适用于 OrcaView `analysis-design-2`。依据为作者官方 2026.11.3 手册，1168 个物理页；正文物理页 = 印刷页 + 21。来源、完整性哈希与全功能清单见 [手册集成清单](MULTIWFN_MANUAL_MAP.md)。

外部依赖按子功能登记。科学输入已准备好后由内置核心完成分析，与从结构开始启动额外量化计算，是两个独立能力。只读解析某种输出，也不等于内置了产生该输出的软件。

## 三种依赖状态

| 状态 | 运行分析时的条件 | OrcaView 行为 |
|---|---|---|
| 外部结果数据 | 已有匹配结果即可，无需在本机运行原软件 | 检查数据语义、来源与几何；满足条件后由内部核心分析 |
| 额外计算或程序 | 目标量尚未生成，或原功能直接依赖额外程序 | 单独任务/插件；用户配置工具及相应使用条件 |
| 可选辅助工具 | 转换、绘图、加速或某种可替换的数据来源 | 不作为整个分析族的硬依赖 |

这与软件构建所需的编译器、OpenMP、BLAS/LAPACK 等数值运行时不同。后者属于随引擎管理的构建依赖，见 [内嵌引擎设计](../MULTIWFN_ENGINE_DESIGN.md)。

## NBO 与 GENNBO 相关能力单列

| 能力 | 最小外部数据 | 手册与印刷页 | 集成边界 |
|---|---|---|---|
| NBO/NLMO 等轨道显示 | `.31` 基组和对应 `.32–.40` 轨道系数文件 | §2.5 p17；§4.0.2 p445–447 | 可以导入/显示；不能称为 OrcaView 内置求解 NBO |
| NAO 轨道组分 | 含 `NAOMO` 的 NBO/GENNBO 输出 | §3.10.4 p116–117 | 基础波函数不自动提供该矩阵；普通 Mulliken/SCPA/实空间组分另行可用 |
| NAO-Wiberg、NAO 多中心键级及分解 | 含 `DMNAO` 的输出 | §3.11.2 p121–123；§3.11.8 p129–130 | 与不依赖 NBO 的 Mayer、Löwdin-Wiberg 分开注册 |
| AV1245 / AVmin 的 NAO 分支 | NBO `DMNAO` | §3.11.10 p131–133 | 原始 AO 分支无需 NBO，但有弥散基组适用性限制；不能整项划为外部依赖 |
| AdNDP 分析 | 含 NAO 信息及 `DMNAO` 的 NBO/GENNBO 输出 | §3.17.2 p197–198；汇总 p200 | AdNDP 数值算法可复用，但 NAO 数据不是普通 Molden 直接生成；用户选择/耗减历史应保存 |
| AdNDP 轨道显示/导出 | 另需 `AONAO` 与匹配 `.fch` | 同上 | 该版手册的独立 GENNBO 输出路径不能直接提供等价可视化；不得承诺仅 DMNAO 即可画轨道 |
| AdNDP 轨道能量 | 再需同体系、同计算水平的 Fock/KS 矩阵 | §3.17.2 p198 | 原子、基函数与表象严格对应 |
| Yoshizawa 电子输运路径 | `NAOMO` 与相应波函数 | §3.100.18 p379–380 | 不与普通片段重叠/转移积分混合 |
| GENNBO 输入准备 | Multiwfn 可导出 `.47` | §3.100.2 p364–365 | 只生成输入，不表示运行 NBO；外部执行为独立适配器 |
| NPA、NBO E(2)、deletion 等 NBO 结果 | 由 NBO 生成的相应输出 | §4.A.5 p1086 对 E(2)/deletion 与 Multiwfn 本身功能作了区分 | 可做结果导入或可选 NBO 调用，不宣称已复用 Multiwfn 的 NBO 求解算法 |

NAdO（§3.200.20）与 AdNDP 不是同一种方法；Boys/PM 局域化也不等于 NBO。NEDA、NRT 在该固定 PDF 全文按词界检索未检出，当前不登记为 Multiwfn 支持能力；未来若做独立 NBO 适配，按其专门文档另行定义。

默认安装不捆绑 NBO/GENNBO。用户已取得的数据可以按能力导入；主动调用时另行配置可执行文件、版本与使用条件。不能为了移除依赖而自行用其他轨道近似冒充 NAO 或 NBO。

## 原流程需要额外计算或专门结果的能力

| 能力 | 依赖与可替代条件 | 手册与印刷页 | OrcaView 范围 |
|---|---|---|---|
| 形变/原子参考波函数 | 缺 `atomwfn/*.wfn` 时原流程调用 Gaussian；完整参考已存在可免调用 | §3.7.3 p77–78 | 参考数据管理与生成分开；不能把内置球平均密度与任意原子波函数完全等同 |
| Hirshfeld-I | 所需 `atmrad/*.rad` 缺失时可调用 Gaussian；完整参考库可直接使用 | §3.9.13 p94–96 | 参考库就绪后可由内部核心计算；库的元素/态/方法与来源明确 |
| CDFT/Fukui/双描述符 | 常规 N/N±1 可用 Gaussian 或 ORCA 计算，也可导入；部分扩展需更多态 | §3.25.2 p324–325；§3.25.4.2 p329–330 | 常规路径优先支持 ORCA；自旋极化开壳层专用流程手册只明确给出 Gaussian 路线，ORCA 另验；各态几何、方法和原子映射一致 |
| EDA-SBL | Gaussian `ExtraLinks=L608` 与 `.fch` 的专门能量分量 | §3.24.2 p316–318 | 内部后处理不等于内部提供全部能量项；按版本/泛函限制开放 |
| sobEDA/sobEDAw | Gaussian + Multiwfn + `sobEDA.sh` 计算流程 | §3.24.3 p318 | 独立外部工作流，不是基础 ORCA 后处理；不能仅换命令名就宣称 ORCA 兼容 |
| 原子色散贡献/色散密度 | 作者修改的 `dftd3`，通过 `dftd3path` 调用 | §3.24.4 p318–320 | 原模块固定为 B3LYP 参数 D3(BJ)；不宣称通用 D3/D4。PBC 分支排除 |
| ICSS、NICS 1D/2D 扫描 | 原流程生成探针并读取 Gaussian NMR 结果 | §3.28.3 p356–358；§3.28.13/.14 p361–363 | 磁屏蔽计算归外部引擎；已有数据可重用。ORCA 适配需单独验证探针/张量格式 |
| 倾斜/非平面环 NICSZZ | 外部量化软件的屏蔽张量，可手动输入 | §3.28.4 p358–359 | 张量分析可内置；不要求把 Gaussian 视作唯一来源 |
| （超）极化率密度 | 该版教程以 Gaussian 有限外场 `.wfx` 供差分分析 | §3.27.3 p351–353 | 通用响应密度分析与特定生产软件适配分开；ORCA 有限场路径需独立验证 |
| ROA 的特定输入路径 | 该版手册未支持 ORCA→Multiwfn 的 ROA 数据通路 | §3.13 p148 | 若保留 ROA，按实际合格数据入口单列支持；不因算法可复用就宣称普通 ORCA 振动输出可用 |
| Gaussian 专门谱分解 | RIC、部分 IR 强度分解所需专门输出 | §3.13.6 p156–160 | ORCA 原子正常坐标 PVS/PVDOS 可另做；不能将整个振动分析排为 Gaussian 依赖 |
| RESP/RESP2/1.2CM5 从结构一键计算 | 手册有 Gaussian 与 ORCA 脚本变体 | §4.7.7.8 p573；RESP2 p577；CM5 p581 | 电荷拟合与上游计算分开；这些方法不能整体标为 Gaussian 必需 |

| GIMIC/AICD | 磁感应电流等外部计算/数据 | §2.5 p19；相关网格示例 p773 | 可按受支持标量网格导入，不能称为内置磁电流计算；`.vti` 支持范围单列 |

ORCA 是产品服务的上游计算引擎，仍由用户独立安装。自带 Multiwfn 来源分析核心不等于捆绑 ORCA，也不意味着能直接解析任意版本 `.gbw`。

## 不应列为数值分析硬依赖的工具

- **VMD、VESTA、ParaView、gnuplot、Origin**：主要用于原版教程的外部绘图、渲染或曲线处理。OrcaView 自己读取数值、绘图和渲染；导出给这些工具可以保留为可选操作。VMD 脚本见 §4.A.14 p1125–1126。
- **GaussView、Antechamber**：EDA-FF 的原子赋型可用它们辅助，但该算法有内部参数与数据输入路径；不能视为 EDA-FF 必需的量化引擎。见 §3.24.1 p313–316。
- **ADF**：Multiwfn 的 NOCV 分析不因此要求 ADF 安装。§3.26.2 p336–338 明确能量估计不采用标准 F_TS，不能把“无需 ADF”改写成“严格完整 ETS 能量分解已内置”。
- **Gaussian**：不应成为普通密度、内部 ESP、Mayer、Löwdin-Wiberg、Boys/PM、很多原子空间积分与网格分析的普遍依赖。

## 功能注册需要表达的依赖

每项功能至少记录 `dependency_kind`、`required_dataset_types`、`optional_producers`、`required_executables`、`supported_backend_builds`、`method_limits` 和 `citations`。这些是计划字段，不是已经上线的 API。

例如 AdNDP 的分析记录应表达“内部算法 + 外部 DMNAO 数据”，不能只写“需要 NBO 安装”，因为本机可以只导入已有结果；sobEDA 的全流程则确实包含额外计算和脚本；ESP 有内部数值路线，`cubegen` 只作为可选加速器。

依赖缺失时界面保留已有可查看数据，明确指出缺少矩阵、状态或工具；不得将原始 AO 结果替代 NAO、将总 D3 能量替代逐原子分解、或把近似密度静默当真实波函数结果。
